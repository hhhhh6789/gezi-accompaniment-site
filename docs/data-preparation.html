1. 实验目标与边界

构建来源可追溯、质量经过审核、时间关系明确，并经约定训练输入接口核验的歌仔戏人声—伴奏配对数据集。人声提供旋律条件，伴奏提供对应的学习目标。

929 包含完整的数据准备流程：小规模验证 → 规模化收集与处理 → 质量及训练输入核验 → 数据划分与交付。规模化建集原本就在本实验范围内，不以当前三份试验录音作为最终数据规模。

正式微调、长期训练、生成效果评价和完整论文训练配方复现另开实验。达到约定数据规模、完成固定交付项并经用户验收后结束 929，不自动增加规模或延伸新研究。

3.2 结构分段与配对完整性通过

13 个片段的共同边界均经用户确认，保留片头伴奏、过门和尾奏。每对来自同一次分离、同一采样边界；各录音的片段重新拼接后与完整分离轨逐样本一致，说明分段没有遗漏内容。

两段超过 30 秒的片段完整保留，没有按固定时长截断。同源裁切和完整覆盖已验证，但缺少独立干净双轨，不能宣称所有分离细节都达到真值意义上的精确对齐。

3.3 训练输入与频谱解码的有限验收通过

  • 旋律与目标特征：13 对片段完成冻结 Chroma/VQ 特征核验，以及实验伴奏目标的尺度、时间网格和全长检查。
  • FM 主损失接口：13 个全长单样本、7 个混合长度批次的前向与反向检查通过；损失和梯度有限，梯度非零。前向是计算预测，反向是计算参数变化方向，本轮没有真正更新参数。
  • 变长提示与补齐：按每段真实长度选取已知伴奏提示，保留学习位置；7 次补齐内容扰动检查通过，有效预测和损失不受补齐内容影响。
  • 声码器解码：短、中、长三段完成频谱到声音的转换及时间/长度核验，用户反馈“都自然完整，没有新增失真”；19 个 CPU 窗口/长度数学案例也通过。

这证明已测数据可以进入当前实验的 FM 主损失接口，且三段参考伴奏频谱可以按实验规则重建成声音。声码器重建使用真实伴奏目标频谱，不是 FM 生成的新伴奏，不作为微调效果证据。

4. 本次采用的模型与输入规则

部件或机制 具体作用 本次采用方式
Demucs htdemucs_ft 将完整录音拆成人声和伴奏，准备配对材料 沿用已比较并听验的模型、权重和参数
Chroma + 冻结 VQ 将人声中的音级信息转换为旋律编号，减少直接传入音色与分离细节 24 通道 Chroma、约每秒 50 帧、512 条目码本；不更新 VQ 参数
Mel 伴奏目标 将伴奏波形转换为 FM 学习的频谱矩阵 24 kHz 单声道输入、128 通道 Mel；按均值 −4.92、方差 8.14 做 z-score 标准化
时间网格与解码 让旋律和目标帧对应同一时间中心，并保持输出头尾长度 使用已核验的共同帧中心及解码起点/长度适配，保留参考长度，不补波形零值
FM（流匹配生成模型） 学习如何根据旋律条件，从噪声逐步生成伴奏频谱 本轮核验主损失和梯度，没有优化器更新
Prompt（伴奏提示） 给模型部分真实伴奏，让它学习剩余位置 按真实有效长度选左右提示，默认启用概率 0.3
CFG（条件丢弃与生成引导机制） 训练时让模型学习有旋律/无旋律两种预测 本轮保留训练条件丢弃概率 0.2；它不是生成时的引导强度
Vocos（声码器） 将伴奏频谱转换为可播放波形 使用已有权重；已完成三段重建与用户听验
REPA/MERT 用预训练音乐特征约束 FM 中间表示的辅助训练链路 本轮未实现辅助损失，用户已接受将其列为限制，不追加实现任务

这些输入规则已按有限范围验收，是本实验的处理合同，不宣称作者完整预处理已精确复现。模型职责、输入输出与必要限制详见项目模型与技术说明。

配对清单的 13 条训练输入状态已登记为 passed_experimental_fm_main_loss_interface，含义是“实验 FM 主损失输入接口通过”，不是完整训练器通过。原音、完整双轨、旧运行产物和模型权重保持保留；实验使用独立环境，不复用 Qwen 环境。Qwen2-Audio 的早期听音试验不作为当前训练标注依据。

6. 已接受的限制与待验证范围

  • 分离人声仍可能有伪影；Chroma/VQ 改变模型接收旋律信息的方式，不会直接修复已有 WAV，也不能消除伴奏目标中的缺陷。
  • 没有独立干净双轨真值；共同边界、完整覆盖和特征中心检查不能替代所有细部对齐证明。
  • 公开完整训练加载器缺失，源码与检查点存在已记录差异；当前只验证实验主损失接口，没有验证优化器更新、恢复训练或完整作者配方。
  • CFG 训练丢条件概率与论文不同，REPA/MERT 辅助损失未实现；用户已接受按本轮有限范围验收，不为消除这些差异自动追加研究。
  • 声码器听验覆盖三段代表样本，不能写成全部 13 段神经解码或新生成伴奏均已验收。
  • 来源与权利状态仍为待核实；当前按内部技术试验记录，不将文件标为已授权发表或共享。

以上限制随数据交付保留。新来源出现具体质量或接口问题时，先说明实际缺口和有限检查方案；新增或修改实验代码仍先展示核心 diff、解释输入输出及逻辑，再等待确认。
