4. 本次采用的模型与输入规则

部件或机制 具体作用 本次采用方式
Demucs htdemucs_ft 将完整录音拆成人声和伴奏，准备配对材料 沿用已比较并听验的模型、权重和参数
Chroma + 冻结 VQ 将人声中的音级信息转换为旋律编号，减少直接传入音色与分离细节 24 通道 Chroma、约每秒 50 帧、512 条目码本；不更新 VQ 参数
Mel 伴奏目标 将伴奏波形转换为 FM 学习的频谱矩阵 24 kHz 单声道输入、128 通道 Mel；按均值 −4.92、方差 8.14 做 z-score 标准化
时间网格与解码 让旋律和目标帧对应同一时间中心，并保持输出头尾长度 使用已核验的共同帧中心及解码起点/长度适配，保留参考长度，不补波形零值
FM（流匹配生成模型） 学习如何根据旋律条件，从噪声逐步生成伴奏频谱 本轮核验主损失和梯度，没有优化器更新
Prompt（伴奏提示） 给模型部分真实伴奏，让它学习剩余位置 按真实有效长度选左右提示，默认启用概率 0.3
CFG（条件丢弃与生成引导机制） 训练时让模型学习有旋律/无旋律两种预测 本轮保留训练条件丢弃概率 0.2；它不是生成时的引导强度
Vocos（声码器） 将伴奏频谱转换为可播放波形 使用已有权重；已完成三段重建与用户听验
REPA/MERT 用预训练音乐特征约束 FM 中间表示的辅助训练链路 本轮未实现辅助损失，用户已接受将其列为限制，不追加实现任务
