1. 目前能确认什么

对象为R0011《五更鼓》、种子1024；初始对照取47.356—67.356秒，连续性诊断取其中48.356—56.356秒的8秒纯伴奏。三者使用同一人声条件、数字窗口、生成配置及播放增益；8秒内不跨生成窗口。

模型 实际反馈 尚不能据此写什么
原预训练 用户：“好一些了，现在比之前连贯一些”，相对长程A 原模型整体合格、原模型优于短程，或本次原模型的戏曲风格评分
504步短程，原B 初始两者均较像戏曲；短程8秒“好一点点”，相对长程A 短程已经连贯、碎片感消失、整体好听
1820步长程，原A 初始更贴合；后续明确碎、不连贯、不好听；不跨窗口的纯伴奏内也有此感受 长程整体胜出、所有录音都退化或训练越久必然越碎

原模型与短程没有直接排序，不能依据“好一些”与“好一点点”的措辞比较二者。贴合度来自初始20秒混合试听，连续性来自后续8秒纯伴奏诊断，不将不同维度和范围混成一个总分。初始反馈保存后，仅揭示这组映射；后续该组诊断已知模型身份，不追称盲听。

已知唯一接缝在原20秒第10.004秒，而不跨接缝的纯伴奏也被听出碎片感，因此该拼接不能独自解释现象。现有反馈不能确定声码器、训练目标、输入表示或数据的具体作用，也不能仅归因于数据少。

这一轮局部对照到此收住：仍只有1首、1种子、1个原始对照案例，不继续切更多段或要求反复试听。全部原话与音频身份见05听验记录和反馈目录（本轮未发布此证据文件）。

2. 下一步为什么检查声码器

现有生成路径是“人声旋律编号 → FM → 生成频谱 → 声码器 → 伴奏声音”。FM是根据旋律条件生成伴奏频谱的流匹配模型；声码器负责把频谱还原为声音。

用户在该方案后回复“继续”，现已完成一次“真实伴奏的交付频谱 → 同一冻结声码器 → 重建声音”，暂时绕过FM。这样可判断声码器与当前目标表示能否在这个位置保留参考伴奏的连续性，然后再决定应优先检查还原链路，还是生成与微调策略。

这是使用已知参考目标的技术检查，不是根据人声生成的效果样本，不能把重建音频混入主模型成绩。929保持已验收，不重做分离或安排逐首原音复验；本次仅因生成质量问题拟定一个固定位置的模块检查。

7. 下一项小实验：只改变额外条件引导

状态：technical_passed_listening_pending，已执行，音乐判断待反馈。 用户在准备好的两设置方案后回复“下一步”，现已执行。输入为同一长程1820步检查点、同一人声旋律编号与初始噪声；输出为两份完整窗口生成频谱及同位置8秒音频。目的为检查额外引导是否与碎片感有关，不能预先写成修复已生效。

CFG（无分类器条件引导）用有人声条件、无条件两种预测的差异调整生成。本项目实际reverse_diffusion源码（本地未同步，保留云端记录位置）采用以下逻辑，正系数后还会做原实现的幅度重缩放：

flow_cond = diff_estimator(..., cond)  # 含人声旋律条件
flow_guided = flow_cond + cfg * (flow_cond - flow_uncond)  # cfg > 0时执行

这不是直接替换源码的diff，而是现有逻辑的简写。输入为当前频谱状态、时间、掩码和人声条件，输出是下一步的频谱变化方向。本实现cfg=0仍保留人声条件；cfg=1仍有额外引导，不能误称为关闭。 cfg=0还会跳过关联的重缩放分支；因此实验检验整个额外引导分支，不能把差异进一步归到“外推”或“重缩放”其中一项。
