929 训练输入规格 v1：完整音频与短窗口

1. 音频保存与模型读取各做什么

正式音频按已接受的自然段落或整首保留，包含唱句、拖腔、前奏、过门和尾奏。当前前9首29对自然段落、后31首31对整首，共60对；模型读取单元来自这些音频的数字特征，不能重复计入正式音频数量或时长。

数字窗口可以在唱词中间结束，完整WAV保持不变；窗口检查仅覆盖对应局部上下文，不能证明跨窗口音乐连贯性或所有完整父序列FM通过。

2. 输入数组与同一时间网格

数组 含义 格式
tokens 人声经 Chroma/冻结 VQ 转成的旋律编号，尽量减少直接传入音色和分离细节 int64 [T]，编号0–511
target_raw_logmel 对应伴奏的原始频谱，保留以便核验 float32 [T,128]
target_mel 模型使用的标准化伴奏目标 float32 [T,128]，(raw−(−4.92))/sqrt(8.14)

24 kHz单声道、步长480点，旋律与目标共用0+k×480帧中心，间隔20 ms；三数组使用同一个半开帧区间[start:end)。帧数乘20 ms只是网格数量，正式时长仍按波形帧数和采样率计算。

CPU目标分析窗1920点、两侧各反射补边960点，只为分析提供上下文，不修改保存的WAV。原生accompaniment_raw_logmel的240+k×480中心及可能少一帧的结果保留用于诊断；同网格目标从完整伴奏另算，不靠裁齐、插值或补一行伪造对应。

3. 已采用的短窗规则与实际验证范围

3.1 窗口规则

每窗最多1500帧（名义约30秒）。父序列T帧取n=ceil(T/1500)，以edge_i=floor(i×T/n)均分；相邻窗口连续、不重叠，完整覆盖父帧一次。tokens、原始目标与标准化目标同步取窗，局部位置从0开始，父配对、绝对帧范围和哈希用于追溯。

规格上限不等于任意新录音、任意1500帧或完整训练器已通过。完整父序列本身不足1500帧时，可以形成覆盖全父输入的一个窗口，但清单仍按其实际采用的窗口路径登记。

4. “输入通过”具体证明什么

清单状态 当前配对数 已确认的范围
passed_experimental_fm_main_loss_interface 13 各自已测整段主损失、梯度及对应接口
passed_experimental_windowed_fm_main_loss_interface 47 各自已测数字窗口及对应有限接口
pending_experimental_feature_and_fm_interface_validation 0 当前60对已登记对应核验结果

FM根据旋律条件预测从噪声向目标的变化方向，主损失比较方向误差，反向检查误差能传回参数。已测有限结果及混合补齐扰动不等于优化器更新、恢复训练或完整训练器通过；参数更新0次。

沿用按每条真实有效长度选择伴奏提示的适配器，默认启用概率0.3。首轮已有提示/补齐检查；后续多批窗口随机门未启用，不能新增宣称已覆盖提示启用分支。CFG训练丢条件概率0.2保留，不是生成引导强度。

eager注意力、4096位置配置、运行时关闭KV缓存、FP32权重／BF16模型计算及FP32主损失保持。REPA/MERT辅助链路未运行，投影冻结；三个未匹配tag张量明确排除，完整作者训练加载器及训练配方未验证。

三段真实伴奏频谱按已测声码器起点／长度规则重建并通过听验；它们不是FM新生成伴奏。旋律准确性、残留影响、跨窗口连贯性和生成质量仍未由这些输入检查证明。
