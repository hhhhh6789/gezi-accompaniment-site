929 项目模型与技术说明：它们具体负责什么

更新日期：2026-10-01。本文用于随时回看项目中的模型、工具和技术分工；实际运行时间、配置、哈希和验收依据见实验进度记录。涉及“当前进度”的内容是本日期的快照，后续阶段应据实际结果更新。

929 的推进边界：用户已明确包含规模化建集。范围是“小规模流程验证 → 按明确规模建集 → 质量与训练输入核验 → 数据划分和交付”；达到约定规模并完成交付、验收后停止，不自动启动正式微调或其他实验。具体来源与数量/合格时长尚待确定。本文对训练机制的解释是帮助理解项目，不表示后续所有机制都必须在 929 实现。固定交付项与停止规则见进度主文档的“实验目标与边界”和“数据交付与结束条件”。

阅读顺序：先看第 1 节理解整体流程，再用第 2 节查名称；具体作用见第 3–5 节；当前验证范围及文件位置见第 6–7 节。

1. 我们最终要做什么，现在在做什么

最终目标是让模型根据歌仔戏人声中的旋律，生成适合的伴奏。当前正在用三份完整录音验证数据处理与训练输入流程；形成规模化合格数据后，正式微调和生成效果评价属于后续模型实验。

准备材料时，完整录音经过分离得到人声和伴奏。每对唱段的人声提供旋律条件，伴奏提供学习目标。生成新伴奏时，模型接收输入人声中的旋律信息，生成新的声音；它并不是从该输入录音中找回原有伴奏。

flowchart TD
    A[完整录音] --> B[Demucs 分离]
    B --> C[人声轨]
    B --> D[伴奏轨]
    C --> E[听验并按共同边界分段]
    D --> E
    E --> F[人声片段：提取 Chroma]
    F --> G[VQ：转换为旋律编号]
    E --> H[伴奏片段：提取并标准化 Mel]
    G --> I[FM：训练输入与损失核验]
    H --> I
    J[未来生成：旋律编号和随机噪声] --> K[FM：生成伴奏 Mel]
    K --> L[Vocos：转换成伴奏音频]

图中伴奏 Mel 是训练的“答案”，旋律编号是告诉模型要配什么旋律的“条件”。我们已经检查了这些输入能否进入 FM 并计算损失和梯度，尚未更新 FM 参数。之前展示的声码器音频，是把真实伴奏的频谱重新合成为声音，用于核验转换链路；它们不是 FM 新生成的伴奏。

Demucs htdemucs_ft 音源分离模型 从完整录音中得到人声和伴奏，准备成对材料 已采用；三份双轨经用户听验通过

FM / Flow Matching 伴奏生成模型 根据旋律条件，学习从噪声走向伴奏频谱 主损失、梯度与提示/补齐检查通过；未更新参数

“特征”是音频的另一种数值表示；“模型”有学到的参数；“机制”是组织训练或生成的方式。Chroma、Mel、CFG 和 REPA 各有用途，不应都当成独立生成模型。

3. 数据准备和旋律条件

3.1 Demucs 与 MDX23：先把训练材料拆成两部分

输入与输出：输入完整歌曲录音，输出人声轨与伴奏轨；完整录音始终保留。Demucs 可以在内部按窗口处理完整录音，不要求我们先按固定秒数切掉戏曲结构。

为什么用：只有完整混音时，模型无法直接获得“给定人声，对应伴奏”的成对监督材料。分离让我们能构建这些配对，但分离结果只是估计，仍需人工听验。

本次选择：R0001 比较两种方案后，用户认为 Demucs 更好，后续两份录音沿用 htdemucs_ft。公开 MDX23 候选来自 ZFTurbo/MVSEP-MDX23-music-separation-model，提交与权重配置已在进度记录中保存；没有证据证明它是 SingNet 的精确版本。

结果说明什么：三份 Demucs 双轨通过本次人工门槛，适合继续小规模流程验证。人声中仍存在伪影；没有独立干净双轨作真值，因此不能宣称完全分离。伴奏是学习目标，明显主唱泄漏或主要乐器缺损仍会影响后续训练，不能靠旋律瓶颈解决。

3.2 同步分段与配对：让条件和答案讲的是同一段音乐

输入与输出：把同一次分离的人声、伴奏，按同一组时间边界切成一对对片段。现有三份录音得到 13 对，保留片头伴奏、内部过门和尾奏。

为什么用：如果人声片段和伴奏片段截取不同位置，模型会收到错误的对应关系。我们按已听验的结构边界分段，不把 30 秒当成固定截断上限。

已证明与待验证：片段连续覆盖完整双轨，重新拼接后逐样本一致，说明没有在分段中漏掉内容。共同边界和相同长度不单独证明分离轨内部的全部细节都精确对齐。

3.3 Chroma：先提取“唱了哪些音”的信息

它是什么：表示随时间变化的音级能量的特征。例如相隔八度的同类音会归到相同音级附近；它不是唱词、精确乐谱，也不是只含一条基频的轨迹。

输入与输出：输入本实验转换为 24 kHz 单声道的人声，输出 24 个音级通道、每秒约 50 帧的数值矩阵。

为什么用：为伴奏提供旋律线索，同时减少直接把整个人声频谱中的音色和分离细节交给模型。残留乐器也可能改变 Chroma，因此不能把它视为绝对无伪影的旋律真值。

3.4 VQ：把旋律信息变成有限种编号

它是什么：VQ 是向量量化；VQ-VAE 是包含这种量化操作的编码/重建模型。码本可理解为一组已经学习好的特征模板，每段输入特征被匹配成模板编号。

输入与输出：输入 Chroma，输出随时间排列的整数 token。本实验码本有 512 个条目，已检查 token 在 0–511 范围内；编号不是歌词编号，也不直接等于某个音符。

为什么用：进一步压缩旋律条件，使 FM 通过有限的旋律表示接收输入，而不是依赖人声中的全部声学细节。这是我们使用预训练旋律瓶颈的目的。

当前怎么用：加载已有 VQ 权重提取 13 对样本的 token，保持参数冻结。冻结表示权重不更新，仍然会执行特征提取计算。

与伪影的关系：论文把 Chroma 和 VQ 组合为量化旋律瓶颈，针对分离伪影与输入音色依赖设计条件表示。AnyAccomp 论文 §2.1 这发生在进入伴奏生成模型之前，不会直接输出一份被修复的人声 WAV，也不保证所有失真都被消除。

4. 伴奏目标和生成模型

4.1 Mel / log-mel：模型使用的“声音表示”

它是什么：将声音在每个时间窗口中的能量分布按 Mel 频率刻度组织起来，再取对数形成 log-mel。它保留比 Chroma 更丰富的声音结构，但不是可直接播放的波形。

输入与输出：输入伴奏波形，输出“时间帧 × 128 个频率通道”的矩阵。训练时它是目标；生成时 FM 输出同类表示，交给声码器合成声音。

为什么用：让生成模型在频谱表示上学习伴奏，再由声码器处理波形合成。输入旋律条件和伴奏目标的角色不同，不是让模型复制人声的 Mel。

4.2 标准化、时间网格与长度：先让数据含义一致

标准化：本实验采用 (原始 log-mel − 均值) / 标准差，均值为 −4.92，方差为 8.14，标准差取方差的平方根。这是数值尺度变换，不是音频降噪或简单的播放音量归一化。raw 和 z-score 指标准化前、后的表示。

为什么核验：数值尺度不同，会改变 FM 的学习目标，也影响声码器重建。本次 z-score 重建的听感与参考接近，支持当前实验输入尺度；完整公开训练加载器缺失，仍不能据此称为作者精确预处理。

时间网格：每一帧特征对应一个时间中心。24 kHz 下 hop 480，即帧中心间隔 20 ms；原目标 Mel 与旋律 token 的中心约定相差 240 个采样点，即 10 ms。仅把帧数凑成一样，不能解决时间中心差异。

当前实验规则：目标 Mel 与 token 使用 0 + k×480 的帧中心；声码器从完整窗口合成结果的第 960 点取参考长度，处理合成起点约定。规则经数学、技术检查及三段听验支持，没有通过末尾补零掩盖长度缺口；它仍是本实验适配，不能称为作者原版。

4.3 FM：真正学习如何生成伴奏的部分

它是什么：Flow Matching，流匹配。可以理解为学习一套变化方向，使随机噪声逐步成为符合旋律条件的伴奏频谱。这里“噪声”是生成过程的起点，不是给分离人声做降噪。

训练输入与输出：输入旋律 token、真实伴奏目标与噪声的混合频谱、当前时间位置，以及有效长度/提示信息；模型输出当前应该怎样变化的预测。它与已知目标变化方向比较，得到主损失。

生成输入与输出：输入旋律 token 和随机噪声，多步使用模型的预测变化方向，最终得到伴奏 Mel。因此“损失计算通过”和“新伴奏听起来好”需要分别验证。

本次状态：使用下载的预训练 FM，13 个全长单样本与七个混合长度批次的前向/反向检查通过。梯度存在且有限，但没有优化器步骤，参数没有改变。完整正式微调计划尚未实施。用户已确认本轮有限验收，不要求在 929 实现完整作者辅助训练配方。

4.4 Vocos：将伴奏频谱变成可以听的声音

输入与输出：输入与其接口匹配的伴奏 Mel，输出 24 kHz 单声道波形。频谱之外的波形合成细节由声码器完成。

为什么用：FM 的最终输出是频谱，还需要这一转换才能播放。声码器不能替代 FM 学习歌仔戏配器，也不能保证将错误的频谱转换成正确伴奏。

本次核验：使用已有预训练声码器，选短、中、长三段，把真实伴奏目标频谱重新合成为声音。用户反馈修正版自然完整、没有新增失真，支持这三段上的频谱尺度与解码时间/长度规则。未把全部 13 段神经解码都标为听验通过，未将这次重建当作微调生成效果。

5. FM 训练中的几种机制

5.1 Prompt：给一部分伴奏作为提示

含义：这里指真实伴奏的部分频谱区域，不是给聊天模型写的一段文字，也不是人声旋律条件。模型看到这些区域，学习生成其余位置，可用于带伴奏上下文的生成训练。

输入与输出：输入目标频谱、真实长度和提示选择方案；输出哪些帧已知、哪些帧要计算损失的掩码。左右提示表示有效片段开头、末尾的已知区域。

为什么改：原公开分支以批次补齐后的最大长度选提示，短样本可能看不到右提示，甚至没有剩余学习位置。已确认适配按每段有效长度选提示，确保提示在真实范围内且保留损失帧，不新增模型学习参数。

当前状态：默认每批共享 0.3 的启用概率；无提示、仅左、仅右、双侧和三个随机种子的混合检查通过。通过的是已测提示与补齐合同，不是所有可能训练情形的穷尽证明。

5.2 CFG：学会有条件和无条件预测，再用于生成引导

训练作用：随机丢掉旋律条件，让同一模型既学“给定旋律如何生成”，也学“不看这段旋律如何生成”。伴奏目标仍然存在，不是丢掉训练答案。

生成作用：结合有旋律、无旋律两种预测，调节条件对生成方向的影响。引导更强不保证质量更好，适合程度需要生成试听与评价。

必须分清两个参数：训练的条件丢弃概率决定多常拿掉旋律；生成的引导强度决定两种预测如何组合。本地训练代码虽然使用 cfg_scale 这个名字，当前的 0.2 在训练分支中承担的是丢条件概率，不能解释为生成引导强度。

当前状态：核验保留本地丢条件概率 0.2。论文训练概率为 0.1，推理引导强度为 3，两者含义不同。AnyAccomp 论文 §2.2、§3.1 后续提案需要明确使用哪种训练设置；本轮没有评价生成引导效果。

5.3 MERT 和 REPA：音乐特征参考与辅助学习约束

MERT 是什么：预训练音乐理解模型。输入符合其接口要求的音频，输出音乐表征，也就是一组描述声音内容的特征；它不是负责合成伴奏的声码器。

REPA 是什么：表征对齐训练方法。取 FM 的中间特征，经过必要的投影/时间对应处理，与预训练音乐模型的表征比较，得到额外的辅助损失。主损失指导变化方向，辅助损失约束中间表示。

为什么用：为 FM 训练提供额外的音乐特征指导。论文使用 MERT-330M 作为 REPA 对齐参考，辅助损失权重为 0.5。AnyAccomp 论文 §3.1 这不同于输入侧的 Chroma/VQ 旋律瓶颈，不能直接把它当成人声音频的伪影清除器。

本次状态：现有模型含 REPA 投影结构，但有结构不等于已计算辅助损失。当前核验将该投影冻结，没有执行 MERT 特征提取和 REPA 损失。教师音频选择、采样率、特征时间对齐与损失细节尚需核查，不能宣称精确复现作者辅助训练。

5.4 Padding 和 Mask：让不同长度片段放进同一批次

含义：padding 是把短样本补到同批最长样本的尺寸；mask 是标记哪些位置属于真实音频。损失 mask 还需排除已经给出的提示区域。

为什么用：计算通常要求一批数据具有相同张量尺寸，但补齐区域不应成为新的训练内容。例如 554 帧和 1,506 帧一起计算，前者有 952 帧补齐，不代表其音乐被延长。

当前证据：七次改变补齐频谱/token 内容的检查通过，有效预测、损失和提示计划保持一致。支持本实验已测批次的处理，不代表可以忽略实际长度记录。

5.5 损失、梯度和优化器：为什么跑过反向仍然没有训练成果

词 具体含义 本次状态
前向 输入数据，得到模型预测 已执行
损失 将预测与目标比较得到的误差数值 主损失已计算；数值不是音质分数
反向传播/梯度 计算各参数应朝哪个方向变化才能影响损失 已核验有限且非零
优化器步骤 按梯度真正修改模型参数 没有执行
检查点 保存模型参数及必要训练状态，供恢复和重载 已加载预训练检查点；本轮未产生微调检查点
微调 从预训练参数出发，用本项目数据更新参数 尚未开始正式微调
冒烟检查 用少量样本快速检查接口和基本计算能否运行 已做多轮；不能据此判断训练效果

当前结果证明输入能进入这套实验主损失计算链路，没有证明模型学到了歌仔戏伴奏。若后续需要临时一步参数更新和检查点重载来验证训练入口，会先给具体方案与核心 diff；长期训练和效果评价仍属于后续实验。

6. 现在下载的 AnyAccomp 是什么，我们之后拟微调什么

下载的 AnyAccomp 包含相互配合的预训练部件：VQ 旋律模型、FM 生成模型、Vocos 声码器。它们已经有作者训练得到的参数；本次加载它们做核验，不是从零训练，也不是下载后就已适配歌仔戏。

未来模型实验的技术路线拟以 FM 为主要微调对象，让它学习歌仔戏配器和伴奏关系；VQ 与声码器当前保持冻结。这不是 929 的自动下一步。最终哪些部件更新、损失怎么组织、数据规模和评价方式如何设置，需要另行确定。加载推理模型不自动提供完整训练程序：公开完整训练加载器缺失，当前使用的是经过确认的实验核验代码。

截至本次更新，已有：三份完整录音的分离听验、13 对分段/配对、冻结旋律特征核验、FM 主损失与变长提示/补齐检查、三段声码器时间/长度与听验。

用户已确认当前小规模流程的有限验收，采用已核验实验输入规则；CFG 条件丢弃概率保留 0.2，REPA/MERT 辅助损失不纳入本轮。下一步确定规模化来源与数量/合格时长。规模化数据收集处理和划分交付已经用户确认属于 929，须在小规模验收后按明确来源与规模推进；正式微调及新伴奏效果评价另行开展。三个检查点 tag 张量没有对应公开模型定义，当前明确排除，不能称为全部检查点与公开源定义精确一致。REPA/MERT 等尚未实现部分须明确记录，不自动变为新增实现任务。
