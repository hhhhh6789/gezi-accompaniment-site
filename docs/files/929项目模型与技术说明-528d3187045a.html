929 项目模型与技术说明：它们具体负责什么

更新日期：2026-10-22。929已验收完成。40首、60对、3316.363242633秒（约55分16秒）；训练／验证／测试32／4／4首、51／4／5对；正式微调尚未开始，参数更新0次。

本文解释模型、特征和机制的作用；最新进度统一看网页正文，数值合同看训练输入规格，交付与划分看数据交付说明。

1. 我们最终要做什么，现在在做什么

最终目标是根据歌仔戏唱腔的旋律信息生成伴奏。929完成的是配对数据准备、有限输入核验、录音级划分和数据交付，已于2026-10-22获得用户最终验收；正式微调和新伴奏生成评价另开实验。

准备数据时，同一次分离的人声提供旋律条件，伴奏提供学习目标。未来生成时，FM根据旋律条件生成新的伴奏频谱，再由声码器合成声音；分离、重建和生成分别承担不同任务。

flowchart TD
    A[完整录音] --> B[Demucs 分离]
    B --> C[人声轨]
    B --> D[伴奏轨]
    C --> E[听验后按共同边界配对：自然段或整首]
    D --> E
    E --> F[人声音频：提取 Chroma]
    F --> G[VQ：转换为旋律编号]
    E --> H[伴奏音频：提取并标准化 Mel]
    G --> I[FM：训练输入与损失核验]
    H --> I
    J[未来生成：旋律编号和随机噪声] --> K[FM：生成伴奏 Mel]
    K --> L[Vocos：转换成伴奏音频]

原始录音、完整双轨、共同边界和听验记录可以供其他方法复用。AnyAccomp的VQ编号、Mel尺度及FM接口是模型专用约定；更换方法时需从保留的WAV重新适配和验证，现有接口通过不能自动作为新模型通过。分离双轨保留伴奏残留和伪影限制，缺少独立干净真值。

2. 名称速查：各自承担什么工作

Demucs htdemucs_ft 音源分离模型 从完整录音中得到人声和伴奏，准备成对材料 40首完整双轨已采用；36首有实际听验记录、4首按批次规则采用，人声轨伴奏残留限制保留
公开 MDX23 候选 音源分离方案 与 Demucs 比较同一份 R0001 的分离结果 已比较；用户认为 Demucs 更好

Chroma 音乐特征表示 从人声提取随时间变化的音级信息 60对已提取并核验；音高分布的数值可用，旋律准确性及残留影响待验证

FM / Flow Matching 伴奏生成模型 根据旋律条件学习从噪声走向伴奏频谱 13整段＋47窗口有限接口已登记通过，0待核验；误差和梯度可计算，参数更新0次
Vocos 神经声码器 将伴奏频谱转换为可播放波形 三段重建及时间/长度适配听验通过
Prompt 已知伴奏提示机制 给 FM 部分真实伴奏，让它学习其余位置 逐条有效长度适配已核验

MERT 预训练音乐特征模型 为辅助训练提供音乐表征参考 当前核验未调用这条辅助链路

特征是音频的数值表示；模型含有学习得到的参数；机制组织模型的计算。不能把Chroma、Mel、Prompt、CFG和REPA都当作独立伴奏生成模型。

批次筛查与人工听验

筛查以分离双轨为输入，输出优先复核名单。五首已听验试点的整轨人声RMS减伴奏RMS为0.39～4.40 dB，向外取整后以[0,5] dB为固定参考范围；范围外、整轨过弱、浮点峰值过高或伴奏连续近零触发复核。未触发者按来源ID的固定哈希排序，每批抽取前两首，异常首另计。

这些数值不能识别歌词泄漏、拖腔完整性或全部伪影；五个正例不足以确定漏检率。抽样失败时暂停该批并扩听或由用户判断。最终36首有完整双轨听验记录，R0020、R0032、R0034、R0040按已确认批次规则采用，没有逐首听验；不能把有限输入通过反推为人工听验通过。

3. 数据准备和旋律条件

3.1 Demucs 与 MDX23：先把训练材料拆成两部分

输入完整混音，输出估计的人声轨和伴奏轨；原始录音保留。首轮R0001比较公开MDX23候选与Demucs后，用户采用Demucs htdemucs_ft，后续沿用同一分离方案。公开MDX23候选来自ZFTurbo/MVSEP-MDX23-music-separation-model，没有证据证明它就是SingNet的精确版本。

完整双轨经逐首听验或明确的批次规则采用。人声轨仍有伴奏残留及分离伪影；这不自动等于唱声受损，也不意味着获得独立干净真值。伴奏是学习目标，主唱泄漏和乐器缺损仍可能影响后续训练。

3.2 同步分段与配对：让条件和答案讲的是同一段音乐

当前前9首保留29对自然段落，后31首各保留一对整首，共60对。人声与伴奏取同一分离版本和共同采样边界，保留完整唱句、拖腔、前奏、过门和尾奏；正式收录原样保存已采用音频，模型数字窗口不增加正式配对数或时长。

RMS低能量定位只提供候选线索，不能代替音乐结构判断。R0004旧RMS切点被否决的事实保留；后来采用的新边界由完整试听确认。共同边界和可完整重拼证明裁切覆盖，不单独证明所有分离细节达到真值意义上的精确对齐。

3.3 Chroma：先提取“唱了哪些音”的信息

它是什么：表示随时间变化的音级能量的特征。例如相隔八度的同类音会归到相同音级附近；它不是唱词、精确乐谱，也不是只含一条基频的轨迹。

输入与输出：输入本实验转换为 24 kHz 单声道的人声，输出 24 个音级通道、每秒约 50 帧的数值矩阵。

为什么用：为伴奏提供旋律线索，同时减少直接把整个人声频谱中的音色和分离细节交给模型。残留乐器也可能改变 Chroma，因此不能把它视为绝对无伪影的旋律真值。

3.4 VQ：把旋律信息变成有限种编号

它是什么：VQ 是向量量化；VQ-VAE 是包含这种量化操作的编码/重建模型。码本可理解为一组已经学习好的特征模板，每段输入特征被匹配成模板编号。

输入与输出：输入 Chroma，输出随时间排列的整数 token。本实验码本有 512 个条目，已检查 token 在 0–511 范围内；编号不是歌词编号，也不直接等于某个音符。

为什么用：进一步压缩旋律条件，使 FM 通过有限的旋律表示接收输入，而不是依赖人声中的全部声学细节。这是我们使用预训练旋律瓶颈的目的。

当前60对均已使用冻结VQ权重生成旋律编号并核验；冻结表示不更新权重，提取时仍执行模型计算。编号合法仅说明数值满足约定，不证明旋律语义准确。

与伪影的关系：论文把 Chroma 和 VQ 组合为量化旋律瓶颈，针对分离伪影与输入音色依赖设计条件表示。AnyAccomp 论文 §2.1 这发生在进入伴奏生成模型之前，不会直接输出一份被修复的人声 WAV，也不保证所有失真都被消除。

按特征原理推断，无唱声处的残留乐器也可能形成音级条件，演唱中的残留可能与唱腔混合；这是待验证的影响分析。当前没有因为该解释新增静音、裁剪、过滤或去伪影处理。

4. 伴奏目标和生成模型

4.1 Mel / log-mel：模型使用的“声音表示”

它是什么：将声音在每个时间窗口中的能量分布按 Mel 频率刻度组织起来，再取对数形成 log-mel。它保留比 Chroma 更丰富的声音结构，但不是可直接播放的波形。

输入与输出：输入伴奏波形，输出“时间帧 × 128 个频率通道”的矩阵。训练时它是目标；生成时 FM 输出同类表示，交给声码器合成声音。

为什么用：让生成模型在频谱表示上学习伴奏，再由声码器处理波形合成。输入旋律条件和伴奏目标的角色不同，不是让模型复制人声的 Mel。

4.2 标准化、时间网格与长度：先让数据含义一致

标准化：本实验采用 (原始 log-mel − 均值) / 标准差，均值为 −4.92，方差为 8.14，标准差取方差的平方根。这是数值尺度变换，不是音频降噪或简单的播放音量归一化。raw 和 z-score 指标准化前、后的表示。

24 kHz下步长480点，token与当前伴奏目标共用0+k×480帧中心，间隔20 ms。原生Mel保留240+k×480帧中心及可能少一帧的差异，仅供诊断；不能通过简单裁齐、插值或补一行把它当作同网格目标。

CPU从完整伴奏另算目标：分析窗1920点、步长480点，两侧反射补边960点，为分析窗提供上下文，不改写保存的WAV；目标为float32的[T,128]，与旋律编号同长。三数组的尺度、有限值、编号保持和对应关系已按各自记录核验，完整数值规则见训练输入规格。

声码器实验适配从完整窗口合成结果第960点取参考长度，保留真实头尾长度，不在波形末尾补零掩盖缺口。三段真实目标频谱的重建听验支持所测尺度和解码约定；这是项目适配，尚不能称为作者完整预处理的精确复现。

4.3 FM：真正学习如何生成伴奏的部分

它是什么：Flow Matching，流匹配。可以理解为学习一套变化方向，使随机噪声逐步成为符合旋律条件的伴奏频谱。这里“噪声”是生成过程的起点，不是给分离人声做降噪。

训练输入与输出：输入旋律 token、真实伴奏目标与噪声的混合频谱、当前时间位置，以及有效长度/提示信息；模型输出当前应该怎样变化的预测。它与已知目标变化方向比较，得到主损失。

生成输入与输出：输入旋律 token 和随机噪声，多步使用模型的预测变化方向，最终得到伴奏 Mel。因此“损失计算通过”和“新伴奏听起来好”需要分别验证。

当前60对分别登记为13对整段有限接口通过与47对窗口有限接口通过，合计139个读取单元。所测前向、主损失、梯度和变长补齐结果证明对应计算链路可用；参数没有据此更新，生成质量没有据此通过。

R0005的94.77秒、4739帧完整父段在eager注意力前向显存不足，原失败保持；后续局部窗口成功不改写它。4739帧超过未改动的4096位置配置，位置部件检查不证明完整FM超范围行为可用。不能据一次显存不足判定其他省显存方法必然不可行。

4.4 Vocos：将伴奏频谱变成可以听的声音

输入与输出：输入与其接口匹配的伴奏 Mel，输出 24 kHz 单声道波形。频谱之外的波形合成细节由声码器完成。

为什么用：FM 的最终输出是频谱，还需要这一转换才能播放。声码器不能替代 FM 学习歌仔戏配器，也不能保证将错误的频谱转换成正确伴奏。

本次核验：使用已有预训练声码器，选短、中、长三段，把真实伴奏目标频谱重新合成为声音。用户反馈修正版自然完整、没有新增失真，支持这三段上的频谱尺度与解码时间/长度规则。未把全部 13 段神经解码都标为听验通过，未将这次重建当作微调生成效果。

5. FM 训练中的几种机制

5.1 Prompt：给一部分伴奏作为提示

含义：这里指真实伴奏的部分频谱区域，不是给聊天模型写的一段文字，也不是人声旋律条件。模型看到这些区域，学习生成其余位置，可用于带伴奏上下文的生成训练。

输入与输出：输入目标频谱、真实长度和提示选择方案；输出哪些帧已知、哪些帧要计算损失的掩码。左右提示表示有效片段开头、末尾的已知区域。

为什么改：原公开分支以批次补齐后的最大长度选提示，短样本可能看不到右提示，甚至没有剩余学习位置。已确认适配按每段有效长度选提示，确保提示在真实范围内且保留损失帧，不新增模型学习参数。

当前状态：默认每批共享 0.3 的启用概率；无提示、仅左、仅右、双侧和三个随机种子的混合检查通过。通过的是已测提示与补齐合同，不是所有可能训练情形的穷尽证明。

5.2 CFG：学会有条件和无条件预测，再用于生成引导

训练作用：随机丢掉旋律条件，让同一模型既学“给定旋律如何生成”，也学“不看这段旋律如何生成”。伴奏目标仍然存在，不是丢掉训练答案。

生成作用：结合有旋律、无旋律两种预测，调节条件对生成方向的影响。引导更强不保证质量更好，适合程度需要生成试听与评价。

必须分清两个参数：训练的条件丢弃概率决定多常拿掉旋律；生成的引导强度决定两种预测如何组合。本地训练代码虽然使用 cfg_scale 这个名字，当前的 0.2 在训练分支中承担的是丢条件概率，不能解释为生成引导强度。

当前状态：用户已确认 929 保留本地丢条件概率 0.2。论文训练概率为 0.1，推理引导强度为 3，两者含义不同。AnyAccomp 论文 §2.2、§3.1 正式微调设置另行确定；本轮没有评价生成引导效果。

5.3 MERT 和 REPA：音乐特征参考与辅助学习约束

MERT 是什么：预训练音乐理解模型。输入符合其接口要求的音频，输出音乐表征，也就是一组描述声音内容的特征；它不是负责合成伴奏的声码器。

REPA 是什么：表征对齐训练方法。取 FM 的中间特征，经过必要的投影/时间对应处理，与预训练音乐模型的表征比较，得到额外的辅助损失。主损失指导变化方向，辅助损失约束中间表示。

为什么用：为 FM 训练提供额外的音乐特征指导。论文使用 MERT-330M 作为 REPA 对齐参考，辅助损失权重为 0.5。AnyAccomp 论文 §3.1 这不同于输入侧的 Chroma/VQ 旋律瓶颈，不能直接把它当成人声音频的伪影清除器。

本次状态：现有模型含 REPA 投影结构，但有结构不等于已计算辅助损失。当前核验将该投影冻结，没有执行 MERT 特征提取和 REPA 损失。教师音频选择、采样率、特征时间对齐与损失细节尚需核查，不能宣称精确复现作者辅助训练。

5.4 Padding 和 Mask：让不同长度片段放进同一批次

含义：padding 是把短样本补到同批最长样本的尺寸；mask 是标记哪些位置属于真实音频。损失 mask 还需排除已经给出的提示区域。

为什么用：计算通常要求一批数据具有相同张量尺寸，但补齐区域不应成为新的训练内容。例如 554 帧和 1,506 帧一起计算，前者有 952 帧补齐，不代表其音乐被延长。

首轮已有提示与补齐适配检查；后续各批次仅支持其实际运行的单窗、混合批次和扰动范围。多轮后续窗口计算没有随机启用伴奏提示，不能新增宣称提示启用分支已覆盖，也不能由一次混合批次推断所有长度组合通过。
