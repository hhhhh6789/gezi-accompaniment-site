伴奏研究型混合架构实现与验收

日期：2026年9月10日

一、交付结论

本次在保留四个旧伴奏profile的基础上新增 research_hybrid_v1。新profile提供统一条件契约、歌仔戏层级时间轴、多候选规则提供器、硬约束、软评分、确定性选择、技术代理指标和版本化追踪信息。

它是研究框架和规则基线，不是训练后的伴奏模型，不代表已经取得听感提升或歌仔戏专业有效性。

二、核心数据流

  1. ConditionBundle 接收网页旧输入或FT-GAN结构条件。
  2. OperaTimeline 构建音符、腔句、区段和前奏/唱腔/过门/尾奏窗口。
  3. RuleCandidateProvider 生成平衡、稀疏、响应型和低位支撑四组候选。
  4. 硬约束淘汰非法时间、音域、重叠、打击乐冲突和采样不具备的候选。
  5. 软评分记录唱腔避让、句末响应、过门覆盖、密度、音级距离、声部多样性和置信度。
  6. 按总分、候选签名和标识符确定性选择结果。
  7. 复用现有MIDI导出、授权采样渲染和人声混音流程。

三、兼容边界

  • generate_accompaniment() 原参数和默认行为保留。
  • prototype_v1、traditional_v1、opera_v2、backstage_v1 均继续可用。
  • Flask后端识别 research_hybrid_v1，但两个网页仍固定提交 backstage_v1 + qizi。
  • 新profile当前只支持七字调；其他曲调会明确拒绝，不静默套用未经定义的规则。
  • 未来学习模型必须实现 CandidateProvider；当前不可用提供器会明确报错，不返回伪造结果。

五、测试验收

执行命令：

$PROJECT_ROOT\.venv\Scripts\python.exe -m unittest tests.test_accompaniment tests.test_backstage_v1 tests.test_research_hybrid

结果：66项测试全部通过，其中原有40项、新增26项。新增测试覆盖条件对齐、中文曲调/板式别名、非法连音、结构边界、候选确定性、随机种子、硬约束、评分排序、不可用学习提供器、元数据以及完整MIDI/WAV渲染。

六、尚未完成

  • 没有训练神经网络。
  • 没有新增或下载未授权训练数据。
  • 没有完成歌仔戏专业听评。
  • 没有证明层级条件相对强基线产生提升。
  • 没有将 research_hybrid_v1 切换为网页默认方案。

因此当前正确表述是“研究框架已实现并通过结构测试”，而不是“创新方法已经验证”。
